2. 감점 요소 (사진 포함)

① 제출 APK 규칙 위반 + 현재 소스와 다른 APK −1.0 (8번)

소스 루트에 Module_C_109.apk가 있다. 규칙은 Module_A_XXX.apk이므로 파일명 규칙(0.5)이 어긋난다. 더 큰 문제는 이 APK(10/30 커밋, 패키지 com.example.untitled)가 현재 소스(11/22 커밋, com.example.test_1)와 다른 빌드라는 점이다. 예를 들어 APK는 이름 2자를 "최소 3자에서 최대 20자여야합니다!" 토스트로 거부하지만 소스는 2자를 허용한다. "제공된 APK로 평가"(0.5)도 미충족으로 봤고, 채점은 소스를 복사본에서 release 빌드해서 진행했다.

※ 대회에서는 제출된 APK로 평가하는 것이 원칙이라, 이 APK로 채점하면 이름 검증 등 여러 항목이 달라진다. 최종 제출 직전 반드시 APK를 새로 빌드해 이름을 Module_A_번호.apk로 바꾸자.

② 온보딩 애니메이션이 2초를 넘는다 −1.2 (10번)

달 1.0~1.5초, 구름 1.6~2.1초, 로고·문구 2.3~3.6초, 버튼 3.6~4.6초 순서로 끝난다. 요구사항은 "달·구름", "로고·문구", "버튼"이 각각 2초 이내에 애니메이션되는 것이다. 시작 시점 기준으로 세 항목(각 0.4)이 모두 2초를 넘는다. 실제 첫 화면 표시까지 0.6초가 더 걸리고, 시작 후 4~5초가 지나야 버튼을 누를 수 있다.

※ 구름은 0.1초 차이의 경계 사례이고, "애니메이션 1개가 2초 이내"로 해석하면(각 1초 이하) 모두 충족이다. 심사위원 합의 사항이다.

위치: lib/main.dart:53-81 (Future.delayed 1000/600/700/300/500/500ms)

③ 수정하러 돌아갈 때 이전 버튼·진행 막대가 보이고, 수정 후 확인 화면으로 돌아오지 않는다 (주관)

확인 화면에서 이름 영역을 누르면 이름 화면으로 이동하지만, 일반 입력 때와 같은 이전 버튼과 진행 막대가 그대로 보인다 (캡처 29). 입력칸은 비어 있고(기존 값 유지 안 됨), 이름을 고치고 Enter를 누르면 확인 화면이 아니라 나이 화면으로 간다 (캡처 29b). 결국 하나만 고치려 해도 나이·성별·날짜·시간을 전부 다시 거쳐야 한다. 수정 중에는 이전/다음 버튼 없이 바로 확인 화면으로 돌아오는 것이 자연스럽다.

채점표 22번 요구사항 2번("해당 입력 화면으로 다시 이동")은 충족이라 객관 감점은 하지 않았고, 정보 입력·확인 화면의 주관 등급에 반영했다.

위치: main.dart:248-254 모든 페이지가 onNext에서 go(다음 번호)로 고정이다. 수정 중임을 뜻하는 상태가 없다.

④ 주관 항목에서 점수가 깎인 곳 (주관)

  • 테두리와 글자 굵기. 입력창·성별 박스·확인 영역 테두리가 프로토타입의 옅은 선보다 진한 흰색이고 글자가 더 굵다. 진행 막대도 더 두껍다. (정보 입력·확인 일치도)
  • 연·월 선택창이 기본 Material 다이얼로그다. 보라 테마의 앱 안에서 연한 보라색 흰 창이 떠서 이질적이다 (캡처 19, 20).
  • 빈 홈 화면이 흰색이다. 이전 화면과 같은 그라디언트가 아니라 기본 흰 화면이라 상태바 글자가 보이지 않는다 (캡처 32).
  • 화면 본문이 전환 효과 없이 바뀐다. 입력 요소만 400ms 늦게 페이드인한다. (화면전환 5번)
  • 오류 문구가 모두 같다. 미입력·짧음·김에 같은 문장이다. (친절한 메시지 6번)

3. 코드 리뷰

잘한 점

  • 화면 1개 = 파일 1개(pages/name_page.dart 등)로 나눠 어느 화면을 고칠지 찾기 쉽다.
  • 화면 이동을 go(index) 한 함수로 처리하고, 이전·다음을 onBack/onNext 콜백으로 넘겨 각 화면이 서로를 몰라도 된다.
  • flutter_svg는 pub.dev publisher가 flutter.dev로 확인되어 허용이다. 그 외 외부 패키지는 없다.

정리가 필요한 부분

  • 각 페이지에 쓰지 않는 변수가 복사되어 있다 (showDailyTarot, showgraphic, pageIndex, nameContontroller가 나이·성별·날짜·시간 페이지에도 있다). 이름 오타(Contontroller, valud, progrssBar)도 그대로 복사되었다.
  • 같은 이전 버튼 코드(약 30줄)가 네 파일에 그대로 반복된다. 한 위젯으로 빼면 수정 모드 때 이전 버튼을 숨기기도 쉽다.
  • 입력값 검증이 이름·나이에서 if/else if 세 가지가 같은 문구를 반복한다. 한 줄 조건으로 합칠 수 있다.
  • build 메서드에 @override가 빠진 곳이 있고, 좌표(top: 325, bottom: 62)가 모든 파일에 흩어져 있다.

제출 관리

  • 루트에 오래된 APK와 빈 파일(font)이 남아 있다. 제출 전에 정리하자.
  • 작업 폴더에 windows/ 플랫폼과 변경된 generated_plugin_registrant가 포함되어 있다. 안드로이드 과제에는 불필요한 파일이다.
